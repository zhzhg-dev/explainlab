# ExplainLab

**让系统出一次故障，再亲手理解修复方案。**

[打开在线实验室](https://zhzhg-dev.github.io/explainlab/) · [English](README.md) · [模型说明](docs/MODEL.md)

![重试风暴实验的真实界面](docs/images/retry-storm.png)

ExplainLab 是一个开源的交互式系统实验室。两种策略接收**完全相同的请求流量**，你可以改变负载、超时和并发容量，观察请求如何流动、队列如何积压，以及策略有什么代价。

无需注册、API Key 或后端服务。应用不接第三方行为统计。

## 首版三个实验

| 实验     | 策略对比                                   | 你可以探索的问题                       |
| -------- | ------------------------------------------ | -------------------------------------- |
| 重试风暴 | 固定间隔重试 vs 不重试／指数退避／随机抖动 | 为什么「再试一次」会阻碍系统恢复？     |
| 缓存击穿 | 每个请求独立回源 vs 请求合并               | 一个热点键过期会产生多少重复工作？     |
| 队列拥堵 | 240 个等待槽位 vs 可调有界队列             | 接收更少的请求，能否得到更多有用结果？ |

## 30 秒上手

1. 打开实验室，点击右上角「中文」，运行「重试风暴」。
2. 第 6 秒服务耗时变为 5 倍，第 14 秒恢复。
3. 同时看成功率、请求放大倍数和队列峰值；拖动时间轴可回看。
4. 把请求速率调到 30/s 后重跑。退避不是万能的，过载时两边都可能失败。
5. 「分享场景」复制包含参数、种子和模型版本的链接；「导出」保存当前时刻的真实结果 PNG。

默认重试场景选在可恢复的容量边界附近，方便观察策略差异。它是教学示例，**不代表某种策略在所有情况下都占优**。

## 已实现

- Web Worker 内的确定性离散事件模拟。
- 两组相同请求流量；处理耗时与重试随机数互不干扰。
- 播放、暂停、重置、拖动时间轴、1×–8× 播放。
- 带模型版本且经过校验的场景链接。
- 真实指标、参数、随机种子及版本信息的 PNG 导出。
- 完整英中切换、手机布局、键盘操作、减少动画偏好。
- 单独展示失败、拒绝、待完成请求；p95 明确只计算成功请求。

这是**教学模型，不是真实服务压测或生产容量计算器**。客户端超时不取消服务端工作；缓存命中延迟设为零；缓存实验只模拟一个热点键，不包含网络延迟和分布式锁。详细定义见 [模型说明](docs/MODEL.md)。

## 本地运行

需要 Node.js 24+ 和 npm。

```bash
git clone https://github.com/zhzhg-dev/explainlab.git
cd explainlab
npm ci
npm run dev
```

打开终端提示的地址，通常为 `http://127.0.0.1:5173/explainlab/`。

```bash
npm run check
npm run build
npm run preview
npm run format
```

合并到 `main` 后，GitHub Actions 自动测试、构建并部署 GitHub Pages。Fork 后请在仓库 **Settings → Pages** 选择 **GitHub Actions**；如果改了仓库名，也要修改 `vite.config.ts` 的 `base`。
